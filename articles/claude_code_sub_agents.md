## はじめに

Claude Codeには、複雑なタスクを並列処理したり、専門的な作業を委譲したりするための**サブエージェント機能**がある。
親エージェント（メインの会話）がサブエージェントを起動し、独立したコンテキストで作業を行わせることができる。

本記事では、Claude Codeのサブエージェントの概念・種類・使いどころを解説する。

## サブエージェントとは

サブエージェントとは、親となるClaudeセッションから`Agent`ツールを使って起動される独立したAIエージェント。
それぞれ独立した会話コンテキストを持つため、親の会話履歴は引き継がれない。

主な特徴は次のとおり。

- 親セッションとは独立したコンテキストで動作する
- 特定のタスクに特化した専門エージェントを選択できる
- フォアグラウンド（同期）とバックグラウンド（非同期）の2つの実行モードがある
- `isolation: "worktree"` を指定することでgit worktreeを使った隔離環境で実行できる

## サブエージェントの種類

Claude Codeには用途別に複数のサブエージェントが用意されている。

### 汎用系

| エージェント | 説明 |
|---|---|
| `claude` | 特定のエージェントに当てはまらない汎用タスク向け |
| `general-purpose` | 複数ステップにわたる調査・検索・実行タスク向け |

### 調査・探索系

| エージェント | 説明 |
|---|---|
| `Explore` | コードベースの高速な読み取り専用検索エージェント。ファイル検索・シンボル検索・パターン検索に特化している |
| `Plan` | 実装計画の設計エージェント。ステップバイステップの計画を返す |

### 開発系

| エージェント | 説明 |
|---|---|
| `voltagent-core-dev:frontend-developer` | React/Vue/Angularなどフロントエンド全般 |
| `voltagent-core-dev:backend-developer` | APIやマイクロサービスなどサーバーサイド全般 |
| `voltagent-core-dev:fullstack-developer` | DB・API・フロントエンドを横断した機能実装 |
| `voltagent-core-dev:mobile-developer` | React NativeやFlutterを使ったモバイルアプリ |
| `voltagent-core-dev:ui-designer` | デザインシステムやコンポーネントライブラリの設計 |

### レビュー・品質系

| エージェント | 説明 |
|---|---|
| `doc-reviewer` | ドキュメントの品質レビューと改善提案 |
| `implementation-validator` | 実装コードのスペックとの整合性検証 |
| `claude-code-guide` | Claude Code本体の機能・APIに関する質問への回答 |

## 実行モード：フォアグラウンドとバックグラウンド

サブエージェントは2つの実行モードで起動できる。

### フォアグラウンド（デフォルト）

サブエージェントの完了を待ってから次の処理に進む。
サブエージェントの結果を使って次のステップを判断する場合に使う。

```
# フォアグラウンドで起動（デフォルト動作）
Agent(
  subagent_type="Explore",
  prompt="src/components以下でButtonという名前のコンポーネントを探してください"
)
```

### バックグラウンド

`run_in_background: true` を指定することで非同期に実行できる。
完了通知を受け取るまで他の作業を続けられる。
互いに依存しない複数の調査タスクを同時に走らせる場合に有効。

```
# バックグラウンドで起動
Agent(
  subagent_type="Explore",
  run_in_background=True,
  prompt="テストファイルの一覧を調べてください"
)
```

## 隔離実行：worktreeモード

`isolation: "worktree"` を指定すると、git worktreeを使った隔離環境でサブエージェントが実行される。

```
# git worktreeで隔離した環境で実行
Agent(
  subagent_type="voltagent-core-dev:backend-developer",
  isolation="worktree",
  prompt="新しい認証エンドポイントを実装してください"
)
```

サブエージェントがファイルを変更しなかった場合は、worktreeは自動的にクリーンアップされる。
変更があった場合は、使用されたworktreeのパスとブランチ名が返される。

## サブエージェントの使いどころ

### 並列調査

複数の独立した調査を同時に実行することで、時間を短縮できる。

たとえば、あるバグを調査する際に次の3つを同時に走らせる。

1. エラーが発生しているファイルの特定
2. 関連するテストファイルの確認
3. 最近の変更履歴の確認

### コンテキストウィンドウの保護

長大な検索結果や大量のファイル内容を親セッションに取り込まずに済む。
サブエージェントが結果を処理・要約して返すため、親のコンテキストがクリーンに保たれる。

### 専門エージェントへの委譲

タスクの性質に合った専門エージェントを選ぶことで、より高精度な結果が期待できる。
たとえば、コードベース探索には`Explore`、設計には`Plan`、実装には各開発エージェントと使い分ける。

## プロンプトの書き方

サブエージェントは親の会話コンテキストを持たない。
そのため、プロンプトは**単体で完結する**ように書く必要がある。

良い例：

```
src/auth/login.ts の75行目にある validateToken 関数のロジックを確認してください。
JWTの有効期限チェックが正しく実装されているか検証し、問題があれば指摘してください。
```

悪い例：

```
さっきの関数を確認してください
```

「さっきの関数」という情報は、サブエージェントのコンテキストには存在しない。
ファイルパス・行番号・関数名など、具体的な情報をプロンプトに含める。

## Exploreエージェントの活用

コードベース探索の用途では`Explore`エージェントが特に有効。
`Explore`エージェントには書き込み系のツールが与えられていないため、安全に読み取り専用の調査ができる。

探索の範囲を`breadth`として指定することができる。

- `quick`: 単一の的を絞った検索
- `medium`: 中程度の探索
- `very thorough`: 複数箇所・複数の命名規則を横断した網羅的な検索

## まとめ

Claude Codeのサブエージェントを使うことで、次のようなメリットが得られる。

- 独立したタスクを並列実行して効率を上げる
- 専門エージェントを活用して精度を高める
- 親セッションのコンテキストウィンドウを節約する
- worktreeを使って安全な隔離環境で実装を試せる

サブエージェントへの指示は「コンテキストを持たない同僚への依頼」と考えると書きやすい。
ファイルパスや関数名など具体的な情報を含め、単体で意図が伝わるプロンプトを心がけると良い。
